LESSON 9

Semantic HTML

Semantic tags describe the meaning of a section of content, not just its appearance - which helps browsers, search engines and assistive technology understand the page. This whole site is built from them.

Why semantics matter

A <div> tells a browser nothing about what it contains. A <nav> tells it "this is navigation" - which is exactly why this site's own header uses <nav> for its menu.

The main semantic landmarks

  • <header> - introductory content, usually logo + navigation
  • <nav> - a block of navigation links
  • <main> - the page's primary content, used once per page
  • <section> - a themed group of content, usually with a heading
  • <article> - self-contained content, like this lesson
  • <aside> - related but secondary content, like a sidebar
  • <footer> - closing content, usually copyright and links
Example
<header>...</header>
<main>
<article>
<h1>Lesson title</h1>
<p>Lesson content goes here.</p>
</article>
</main>
<footer>...</footer>
💡

A good rule of thumb: reach for a semantic tag first, and only fall back to a plain <div> when none of them describe the content's role.

Quick Quiz

Check what you just learned - pick an answer for each question.

1. Which tag holds the primary content of a page and is used once per page?

<main> wraps the central content, so browsers and screen readers can jump straight to it.

2. Which tag is best for related but secondary content, like a sidebar?

<aside> is for content connected to the main content but not essential to it, such as a sidebar.
